# П6: техническая приёмка — завершена в согласованном объёме

Дата: 17.11.2026. Проверялись синтетика и ограниченная локальная ASR-сверка на HEAD
`71051bd` (`Fix audited P3-P5 issues`), с полной sandbox-установкой зависимостей.
Рабочая `DATA_DIR`, старые базы и голосовые профили не подключались; миграций нет.
Текущий цикл технической приёмки закрыт по решению владельца. Это не утверждение о
сертифицированной акустической точности, удобстве для всех пользователей или готовности
к миграции реальных данных.

## Проверка совместимости коммита

- Схема осталась v4; миграций и новых runtime-модулей в коммите нет.
- `server.py` не менялся, версия MCP остаётся `2026.11.17.5`; `install.ps1`
  уже включает изменённые runtime-файлы.
- UI истории предлагает возврат только совместимой пары source/review, не предполагая
  совпадения номеров ревизий.
- Локальный `api/start` требует boolean-поля `require_conspect` и
  `allow_cloud_model`; текущая страница отправляет оба. Старый внешний клиент этого
  внутреннего HTTP endpoint без полей получит 400.
- Новые тесты фиксируют безопасный отказ клиента старой версии при схеме v4,
  облачный запрет для уже принятого запроса, отказ устаревшего queued-статуса и
  обход системного proxy только для локального OpenCode API.
- Выявленной несовместимости с контрактами П3–П5 не найдено.

## Известные ограничения и дальнейшие исследования

- Полностью установленное sandbox venv прошло self-check и CLI workflow; MCP и экран
  проверялись отдельно на copy-only runtime. Для `pip check` остаётся описанное выше
  предупреждение distribution-метаданных.
- Синтетическая parity-проверка не измеряет удобство экранов для обычного пользователя;
  такой сценарный прогон можно выполнить отдельно, но он не блокирует закрытие текущей
  технической приёмки.
- Экран на неизвестный synthetic request отвечает 400 с JSON-ошибкой без traceback;
  это проверка технического сообщения, не пользовательское интервью.
- Проведена ограниченная локальная ASR-сверка двух коротких реальных фрагментов:
  один проход и настроенный ансамбль, без профилей/обучения голосов, эмоций и облака.
  Их reference частичные и не прошли полную человеческую проверку, поэтому это
  диагностическое сравнение, не ground truth и не акустическая сертификация.
  Подробные числовые результаты в публичный handoff не включены.
- Один отдельный cloud-workflow проверил конспектирование в sandbox: ASR завершился,
  но модельный шаг и один явно запрошенный retry завершились `offline`; модельного
  результата нет, deliverable `blocked`, document sync `synced`. В запрос модели
  входят текстовые слова/ID, не аудио и не путь к записи. Локальный OpenCode API
  запускался, целевая модель отображается доступной, а сеть до OpenAI достижима;
  это не подтверждает, что любой из двух запросов дошёл до модели или что авторизация
  действительна. Дальнейшие повторы не запускались; выяснение причины оставлено для
  отдельного исследования cloud workflow и локального OpenCode API.
- Порог 30 секунд в профиле — только защита от грубой регрессии; бюджетные пороги
  производительности продукта не утверждены.
- Рабочая `DATA_DIR`, старые базы и голосовые профили не подключались; миграция и
  переключение backend требуют отдельного согласования.

Эти ограничения зафиксированы как границы результатов, а не как незакрытые критерии
текущей приёмки. Приёмка не разрешает подключение или миграцию рабочих данных.
