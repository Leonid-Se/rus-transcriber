# План №1 оптимизации rus-transcriber на платформе AMD

Дата: 2026-11-14. Статус: **частично применено 14.11.2026** (пункты А, Г, шаг 1; Б и В
отложены). Тяжёлые операции — только по отдельному разрешению человека, см. `AGENTS.md`.
Дополнение к разделу «Эта копия: форк; поведение по платформам» в `AGENTS.md` (AMD-пункт).

## Целевая машина

- AMD Ryzen 5 6600H (Zen 3+, 6 ядер / 12 потоков, AVX2, без AVX-512 и VNNI);
- встроенная графика AMD Radeon (RDNA2), драйвер 32.0.21045.16010;
- 16 ГБ ОЗУ, Windows 11 Pro, мини-ПК UM660;
- рабочее окружение программы — установленная копия `%LOCALAPPDATA%\rus-transcriber`,
  в копии репозитория `.venv` нет.

## Выводы анализа (2026-11-14)

1. OpenVINO GPU и NPU — плагины Intel: варианты bench `ov-gpu*`, `ov-npu*`,
   `whisper-gpu` здесь всегда «не работает» и пайплайн откатывается на CPU.
   Это ожидаемое поведение, не баг и не повод править `backends.py`.
2. Основной путь (OpenVINO EP на CPU) полностью рабочий: OpenVINO оптимизирует
   AMD-процессоры по AVX2. Отсутствие VNNI ограничивает скорость int8.
3. `install.ps1` сносит `onnxruntime-directml` (взаимозаменяемые пакеты: модуль
   `onnxruntime` может стоять только один), поэтому бэкенд `dml` в установленной
   копии недоступен — а на AMD это единственный путь задействовать встроенную
   Radeon.
4. Whisper large-v3-turbo остаётся на CPU int8 (тяжело для 6 ядер); вариант
   `whisper-dml` в `bench.py` не добавлен, но технически возможен.
5. 16 ГБ ОЗУ: `max_heavy_jobs: 2` + Whisper int8 + pyannote — впритык; две
   параллельные задачи рискуют свопом.

## Варианты оптимизации

### А. Только настройки `config.json` (код не меняется)

- `max_heavy_jobs: 1`;
- прогон `bench.py --only torch-cpu,onnx-cpu,onnx-cpu-b8,onnx-cpu-b16,whisper-cpu` —
  тест сам выберет `asr_batch` (8 на 6 ядрах реалистичнее 16 из-за RAM);
- `torch_threads: 6` (физические ядра) для pyannote;
- `diar_embeddings: auto` (OpenVINO CPU) — оставить как есть.

### Б. Замена пакета ONNX Runtime (по согласию; меняет окружение установленной копии)

- поставить `onnxruntime-directml` вместо `onnxruntime-openvino`;
- прогнать bench с `dml-gpu`, сравнить с `onnx-cpu`;
- вернуть пакет по результату измерения. Риск: потеря OpenVINO EP, который на CPU
  обычно быстрее голого CPU EP — решение только по измерению.

### В. Доработка форка (отдельная задача, не сейчас)

- bench-вариант `whisper-dml` (DirectML для Whisper): маленький патч `bench.py`,
  защита в `backends.py` уже есть;
- исследование `faster-whisper` (CTranslate2 int8 CPU) или whisper.cpp с Vulkan
  (задействует Radeon) — замена третьей модели, с обязательной проверкой эталоном.

### Г. Вне кода

- план питания Windows «Максимальная производительность», контроль троттлинга.

## Шаги проверки (требуют разрешения)

1. Дёшево и без риска: в установленной копии
   `.\.venv\Scripts\python.exe -c "import backends as b; print(b.openvino_devices(), b.available_providers())"`
   — подтвердить, что OpenVINO видит только CPU. **Выполнен 14.11:** только `CPU`.
2. Прогон bench с `--only` из пункта А (нужен `HF_TOKEN`; скачивание моделей,
   5–15 минут). **Выполнен частично 14.11:** 180 с аудио, `--only onnx-cpu,dml-gpu`.
3. По отдельному согласию — эксперимент с `onnxruntime-directml` (пункт Б) и
   обратный возврат пакета. **Выполнен 14.11:** DirectML медленнее CPU, пакет возвращён.
4. Итог — запись выбора в `config.json` папки данных и краткий отчёт в этом файле.
   **Выполнено 14.11** (см. «Применение»).

## Применение (2026-11-14, без правки кода)

### Настройки, питание, шаг 1 (14.11)

- Шаг 1 выполнен: `openvino_devices()` = `['CPU']`, провайдеры
  `['OpenVINOExecutionProvider', 'CPUExecutionProvider']` — OpenVINO видит только
  CPU, путь «OpenVINO EP на CPU» подтверждён.
- `config.json` папки данных: `max_heavy_jobs: 1`, `torch_threads: 6`,
  `asr_batch: 8` — вручную по готовому bench от 06.11 (b8: 98.0% ≥ порог 97%,
  35 с на 10 мин записи против 88 с у b1; тест сам выбрал b1 из-за приоритета
  точности). `asr_second_batch` оставлен 1: CTC b8 в bench был ниже порога
  (94.8%). `diar_embeddings: auto` — умолчание, не менялось.
- Питание: схема Windows переведена с «Сбалансированной»
  (`381b4222-f694-41f0-9685-ff5bb260df2e`) на «Максимальную производительность»
  (создана копированием скрытой схемы, GUID `404ae727-e587-4348-b6ae-aaf1547ab387`;
  вернуть: `powercfg /setactive 381b4222-f694-41f0-9685-ff5bb260df2e`).
- Контроль троттлинга: базовая частота без нагрузки 3301 МГц при загрузке 11% —
  разгона/троттлинга в простое не видно; проверка под нагрузкой требует
  отдельного разрешения (не выполнялась).

### Пункт Б: DirectML (14.11)

- Пункт Б выполнен 14.11 (по согласию): `onnxruntime-openvino` 1.24.1 заменён на
  `onnxruntime-directml` 1.24.4, прогон bench на том же аудио, что 06.11
  (`--only onnx-cpu,dml-gpu --no-write --no-whisper`). Результат: RNN-T DirectML
  (Radeon) — 22.0×, 33 с на 10 мин записи, совпадение 100%; RNN-T процессор —
  24.7×, 29 с, эталон. DirectML медленнее CPU и не даёт выигрыша — пакет
  возвращён (`onnxruntime-openvino==1.24.1`), провайдеры проверены
  (`OpenVINOExecutionProvider`, `CPUExecutionProvider`). Прежний отчёт bench
  сохранён как `bench\bench_report_2026-11-06.md`; новый — `bench_report.md`.
- Пункт В, часть 1 (14.11, по согласию): в `bench.py` добавлены варианты `ctc-dml`
  («CTC, DirectML») и `whisper-dml` («Whisper, DirectML»); для Whisper в `run_one`
  добавлена ветка `dml` (общий `OnnxASR`, провайдер DirectML; раньше такая строка
  молча уходила бы в CPU). Правка скопирована в установленную копию; bench уже
  входит в `install.ps1`, `VERSION` не менялся.
  Прогон (DirectML-пакет, то же аудио, `--no-write`):
  - CTC DirectML — **29.8×** против CTC CPU 26.1×, совпадение 100%: единственный
    вариант, где Radeon дала выигрыш (~14%, второй проход);
  - Whisper DirectML fp16 — 3.5×, но совпадение 53.2% (текст численно ломается);
  - Whisper DirectML int8 — совпадение 100%, но 0.9× (11.4 мин на 10 мин записи,
    медленнее реального времени; CPU int8 — 2.7×).
  Вывод: Whisper остаётся на CPU int8; вариант `whisper-dml` оставлен в bench с
  int8 (качество-корректный квант) как задокументированная опция для других машин.
  Пакет возвращён (`onnxruntime-openvino==1.24.1`), провайдеры проверены.
  Осталась часть 2: исследование faster-whisper / whisper.cpp — не начиналась.
- Не проверено: влияние настроек на реальных задачах и длинных записях. Повторный прогон
  bench перезапишет `asr_batch` в `config.json` своим выбором; прогон 14.11 шёл с
  `--no-write`, поэтому текущий `asr_batch: 8` сохранён.
