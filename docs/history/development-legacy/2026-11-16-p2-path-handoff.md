## Изменения

- `recordings.document_layout(source, tag)` вычисляет sidecar `<stem>.rus-transcriber`
  и относительные цели `<stem>[.<tag>].transcript.md/json` и
  `<stem>[.<tag>].manifest.json`, не создавая каталоги.
- `Store.get_or_register_root` повторно использует уже зарегистрированный точный
  корень; вложенные/родительские пересечения по-прежнему отклоняются.
- `documents.prepare` принимает относительные цели, сохраняет их в
  `passport.current_paths`, а формат паспорта повышен до версии 2. Materializer,
  сверка и проверка backup читают этот mapping; архивные пути остаются
  ID/revision-based. Версия 1 продолжает читать прежние UUID-цели.
- `storage.create_recording_with_document` записывает выбранные пути в manifest и
  реестр `file_locations`; последующие document revisions наследуют тот же mapping.
  Цели разных recording_id сверяются на коллизии в общей транзакции.

## Проверки и пределы

Синтетический тест создаёт два tag в одном корне, подтверждает разные имена,
повторное использование корня, отказ вложенному корню и отказ коллизии целей;
затем материализует версии, обновляет текущий комплект и проверяет архивы и
`verify_files`.

Runtime приложения ещё не маршрутизирует операции через этот mapping. Старые
записи не переименовывались; реальный sidecar не открывался. Подключение worker,
единого фасада чтения/правок/ответов/конспектов, имени пользователя и инициализации
БД остаётся следующим пакетом П2.
