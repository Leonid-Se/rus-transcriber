# Исследование замены третьей модели: faster-whisper и whisper.cpp

Дата: 2026-11-14. Целевая машина: AMD Ryzen 5 6600H (6 ядер, AVX2 без VNNI),
встроенная Radeon RDNA2, 16 ГБ ОЗУ. Связано с
`docs/amd-optimization-plan-2026-11.md` (пункт В, часть 2).
Статус: **исследование по документации и текущему коду; замеры не выполнялись**.

## Контекст: что сейчас

Третья модель (Whisper large-v3-turbo) в проекте — onnx_asr через `OnnxASR`
(`backends.py`) на CPU int8: **2.7×** (3.9 мин на 10 мин записи, качество 100%
относительно эталона). Проверенные на этой машине GPU-пути не годятся:
Whisper OpenVINO GPU — нет (Intel-плагин), DirectML fp16 — текст ломается
(53%), DirectML int8 — 0.9× (см. план, пункт В часть 1).

## Вариант 1: faster-whisper (CTranslate2, CPU int8)

Что это: переимплементация Whisper на CTranslate2; на CPU декодер пакета
не требует CUDA — `pip install faster-whisper` достаточно (CPU-колёса есть).
Модель подтягивается с Hugging Face в формате CT2 (у turbo есть готовые
репозитории; имена проверять при установке).

- Официальный бенчмарк (i7-12700K, 8 потоков): small int8 с батчем 8 —
  51 с на 13 мин записи (~15×). На нашей машине (6 ядер, без VNNI, модель
  крупнее) ожидание консервативное: **3–6×**, то есть в 1.5–2.5 раза быстрее
  текущих 2.7×. Это оценка, не измерение.
- RAM: int8 turbo ~1.5–2 ГБ — укладывается в 16 ГБ при `max_heavy_jobs: 1`.
- Интеграция: новый класс-обёртка в `backends.py` по образцу существующих
  (интерфейс `transcribe_texts(pieces, progress=...)`, на вход — float32
  16 кГц куски ≤28 с; у faster-whisper `transcribe` принимает numpy-массив),
  подключение в `worker.py` третьей моделью и в `bench.py` как вариант
  `whisper-ct2`. Правки умеренные, всё в Python.
- Новые зависимости: `faster-whisper` (тянет `ctranslate2`, `tokenizers`,
  `av`). Не конфликтуют с `onnxruntime`-пакетами. Нужна запись в
  `install.ps1`/requirements — как договоримся.
- Риски: int8 без VNNI может дать меньший выигрыш, чем ожидаешь; возможны
  отличия в разбиении текста (нужно сверить эталоном — обязательное условие
  плана). На Windows CTranslate2 CPU-инференс стабилен (основной сценарий
  библиотеки).

## Вариант 2: whisper.cpp с Vulkan (Radeon)

Что это: C/C++ реализация Whisper, кросс-вендорный Vulkan-бэкенд — единственный
реалистичный путь задействовать встроенную Radeon для Whisper (см. выше,
OpenVINO/DirectML не работают). Модели в ggml-формате есть, включая
large-v3-turbo.

- Качество на Vulkan/Amd: исторически встречались расхождения fp16-пути на
  разных GPU; наш опыт с DirectML fp16 (текст ломался) показывает, что проверка
  эталоном обязательна и может закончиться отрицательно.
- Интеграция заметно тяжелее, чем у faster-whisper:
  - сборка нативного exe: CMake + MSVC Build Tools + Vulkan SDK
    (`-DGGML_VULKAN=1`), либо готовый exe с релизов;
  - либо Python-биндинги (`pywhispercpp` и т.п. — сторонние, меньше поддержки);
  - exe нужно поставлять установщиком (новый runtime-файл в `install.ps1`);
  - модель ggml (~1.6–3 ГБ) — новый артефакт для скачивания.
- Ожидание по скорости: на RDNA2 iGPU для turbo неопределённое; энкодер
  получит выгоду GPU, декодер остаётся узким местом. Может оказаться и
  медленнее CPU int8 — только измерение покажет.

## Оценка и порядок действий

1. **faster-whisper — приоритет**: дешёвая интеграция (чистый Python), низкий
   риск, гарантированно сохранное качество при проверке эталоном, выигрыш
   вероятен.
2. **whisper.cpp + Vulkan — запасной вариант**: брать только если
   faster-whisper не даст нужного выигрыша; выше интеграционная цена и риск
   неверного текста.

## Что не проверено (требует согласия)

- Реальные замеры: установка `faster-whisper` в окружение установленной копии
  (установка зависимостей — по отдельному разрешению), скачивание CT2-модели
  (~1.5 ГБ), прогон на том же аудио с сверкой эталона.
- Скорость whisper.cpp на Vulkan на этой машине (нужна сборка; не начиналась).
- Интеграционные правки `backends.py`/`worker.py`/`bench.py` — отдельная

## Замер faster-whisper (14.11.2026, по согласию)

Установка: `faster-whisper` 1.2.1, `ctranslate2` 4.9.0 (CPU), модель
`Systran/faster-whisper-large-v3-turbo` int8 (кэш HF в `hf-cache` установленной
копии). **Важно:** faster-whisper тянет обычный `onnxruntime` — пакет
взаимно исключаем с `onnxruntime-openvino`; onnxruntime ему нужен только для
встроенного VAD, поэтому ставится корректно с `--no-deps` + ручные
ctranslate2/tokenizers/av, после чего `onnxruntime-openvino==1.24.1`
восстанавливается. Методика: те же куски ≤28 с (`split_at_pauses`), прогрев,
6 потоков CPU, beam=1; эталон — GigaAM RNN-T CPU b1 на тех же кусках.

Результаты (аудио 180 с):

| Вариант | rtfx | Загрузка | На 10 мин записи | Замечания |
|---|---|---|---|---|
| faster-whisper int8, beam=1 | **3.53×** | 4 с | ~174 с | слов 283 |
| onnx whisper int8 (текущий) | 2.86× | ~92 с | ~234 с | слов 343, **галлюцинация: «бабушка» ×142** |
| faster-whisper int8, beam=5 | 2.84× | — | — | качество как у beam=1 — beam=1 предпочтителен |

Качество: у faster-whisper цикла-галлюцинации нет, хвост текста почти дословно
совпадает с эталоном GigaAM; у текущего onnx-whisper на этом аудио развивается
цикл (в bench это проявлялось и 06.11 — «извините» ×N в `bench_texts.json`).
Итог: **faster-whisper быстрее (~20–25% с учётом загрузки) и надёжнее** —
кандидат на замену третьей модели. whisper.cpp/Vulkan не проверялся — после
такого замера и низкой интеграционной цены faster-whisper стал очевидным
приоритетом.

Не решено: полная интеграция (класс в `backends.py`, подключение в
`worker.py`/`bench.py`, запись в `install.ps1`) — отдельная правка кода по
согласию. Пакет faster-whisper сейчас установлен в venv; onnxruntime-openvino
восстановлен и проверен.
